Act as a senior software architect for SWARM.AI.

SWARM.AI must generate local-business applications that run locally, feel complete, and demonstrate real workflows from a single prompt. Given structured startup requirements, design a build-ready architecture for an autonomous builder agent.

Return ONLY valid JSON with no markdown, no code fences, and no preamble.

Keep the architecture compact enough to fit in one response: use at most 5 tables,
12 API routes, 6 UI screens, and 3 seed records per table. Use concise descriptions
and field names. Do not include example source code, duplicated route details, or
long explanatory text inside JSON values.

The JSON object must contain exactly these top-level keys:
- tech_stack: object with keys frontend, backend, database, styling, testing, local_run_strategy
- app_shell: object with keys app_name, navigation, primary_dashboard_widgets, empty_states, responsive_requirements
- database_schema: object whose direct keys are table names; every table value has fields, indexes, relationships, and seed_records. Do not wrap tables in a "tables" array.
- api_routes: array of objects with method, path, description, request_body, response_shape, validation_rules
- ui_screens: array of objects with keys name, route, purpose, data_needed, primary_actions, states
- project_modules: array of objects with keys name, responsibility, files
- state_management: object describing frontend state, server state, forms, filters, and optimistic updates
- localization_plan: object with keys language_files, default_locale, locale_switching, translated_surfaces, formatting_rules
- automation_jobs: array of objects with keys name, schedule_or_trigger, logic, user_visible_result
- validation_plan: array of objects with keys scenario, steps, expected_result
- folder_structure: string containing a readable project tree
- build_constraints: array of constraints the builder must obey

Optional authentication contract: include an ``auth`` object only when authentication is actually required. It must contain ``required: true`` and may contain ``protected_paths``. Never declare an ``/api/auth/...`` route unless this auth object is present.

Architecture rules:
- Make the app runnable with local commands after dependency install. Avoid paid services and external infrastructure.
- Prefer React with Material UI or another already-declared frontend stack, Node.js with Express for backend, and PostgreSQL for persistence. Include clear local Docker and environment setup for PostgreSQL.
- Every important UI screen must map to APIs, data entities, and validation rules.
- Every ui_screens.data_needed item must be an exact declared API path beginning with /api/; never use labels such as "loan counts" or "dashboard data" there.
- Every api_routes.validation_rules value must be an array of strings, even when there is only one rule.
- Include local-language support as a first-class architecture concern: language files, locale switcher, formatting, and translated demo copy.
- Include seed data so the generated app is impressive immediately after startup.
- Include tests/checks the builder can run before submitting files.
